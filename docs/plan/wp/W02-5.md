## Goal
Compare KanjiVG with KRADFILE decompositions, and stroke counts across sources, for the 2,136 Jōyō kanji, and write the disagreements to a review queue the owner can triage (O-7).

## Acceptance criteria (each must be testable)
1. Decomposition check: per Jōyō kanji, each KRADFILE component (after W01-5 substitutes) must appear among the KanjiVG components at some depth; misses and KanjiVG depth-1 components absent from KRADFILE are queue items, with the 月/⺼ case treated as a match (W01-5 note).
2. Stroke check: KANJIDIC2 stroke count against KanjiVG's path count and Unihan `kTotalStrokes` (Q1); any disagreement is a queue item listing each source's value.
3. The queue is written in the format agreed in Q2: each item has a stable ID (same disagreement, same ID across runs), check name, kanji, evidence per source and a suggested override; items the owner already decided are not re-listed.
4. A CLI command (`pnpm --filter @kizuna/pipeline review:build`) reads the pinned sources, writes the queue and a short summary (counts per check), and exits 0; content-qa can run it.
5. The same inputs give a byte-identical queue (golden from fixtures); a full run's counts go in the handoff.

Options: (a) generated `content/review/queue.yaml` (overwritten each run) plus a hand-edited `content/review/decisions.yaml` keyed by item ID (`accept` or `flag`, reason, author); (b) one file the owner edits in place. Recommendation: a for the first run; the owner's O-7 triage shows which rules b needs. Answered by the owner (session 12): recommendation taken.
