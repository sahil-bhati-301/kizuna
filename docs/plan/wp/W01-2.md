## Goal
Define the `content` schema and its TypeScript types, so parsers have a typed target and later releases can load into Postgres.

## Acceptance criteria (each must be testable)
1. `packages/content` defines every §3.1 entity in a Postgres schema named `content`, with the natural keys the digest gives (kanji `literal`, radical Kangxi number, word `ent_seq`, reading IDs like `生:on:せい`).
2. Every content row type carries `source`, `source_version` and `license`; `mnemonic` and keyword fields are kept apart from dictionary-derived data.
3. `pnpm db:migrate` applies the generated migration on top of the W00-6 baseline, on an empty database and on the Testcontainers harness.
4. Content types are exported only through `packages/content/src/index.ts`; there are no foreign keys to other schemas.
5. `id_redirect` and `content_release` exist; a test shows a `content_release` row cannot be updated once written (immutability rule, arch §7.5).

## Out of scope
- Query API and in-memory release index (later). Loading data. Relation computation (W03).
