## Goal
Stream JMdict into typed `word` rows for a frequency-ranked subset of about 30k entries, with senses and lang-tagged glosses, ready for alignment (W02-3) and sentence links (W02-4).

## Acceptance criteria (each must be testable)
1. The parser streams JMdict XML (with its DTD entities kept as their codes, e.g. `v5k`, `n`) into `word` rows: `ent_seq`, headword, kana, alternative forms with their info tags (`ateji`, `iK`, `oK`, `rK`, search-only), senses with POS and lang-tagged glosses.
2. The headword is the first kanji form that is not search-only or irregular; `kana` is the first reading valid for that headword (`re_restr` respected, `re_nokanji` skipped); kana-only entries use the reading as headword. Text is NFC; kana keep JMdict's script (Q2).
3. The subset and flags follow Q1: an entry is loaded when any form has a priority tag; `is_common` is the standard JMdict rule (news1, ichi1, spec1, spec2 or gai1 on any form); the subset size is reported (30,188 entries on the 2026-11-27 JMdict_e file).
4. `freq_rank` is a dense rank 1..N by best `nfXX` band, then number of priority tags, then `ent_seq`, so ties never depend on input order.
5. The same input gives byte-identical output (golden file from a fixture of about 15 entries covering re_restr, re_nokanji, ateji, kana-only, multi-language glosses and missing nf); every row carries `source`, `source_version`, `license`.
6. The `jmdict` source is pinned in the lock (file per Q3 and week Q-S); a full-file run finishes in under 60 s on a session machine and reports counts.

## Out of scope
- JLPT tags (community lists, later); `jlpt_approx` stays null. Alignment (W02-3). Sentences (W02-4). `id_redirect` for JMdict merges (W03). DB load (W03-5).

## OPEN-Q
- Q1: subset rule. Options: (a) every entry with any priority tag (30,188 today, inside the digest's ~30–50k); (b) only `is_common` entries (22,668); (c) a plus every entry needed to give each Jōyō reading a word. Recommendation: a, because it matches the digest's size and the validation rule only asks for words "where one exists in the loaded word set". Answered by the owner (session 12): recommendation taken.
- Q2: script of `word.kana`. Options: (a) keep JMdict's script (katakana loanwords stay katakana); alignment converts to hiragana before comparing; (b) store hiragana like `reading.kana`. Recommendation: a, because word kana is shown to learners as written. Answered by the owner (session 12): recommendation taken.
- Q3: JMdict file. Options: (a) `JMdict.gz`, all languages (22.2 MB); (b) `JMdict_e.gz`, English only (10.6 MB). Recommendation: a, because the digest keeps lang tags for later i18n and KANJIDIC2 is already loaded with all languages; switching later would churn every word row in a release diff. Answered by the owner (session 12): recommendation taken.
