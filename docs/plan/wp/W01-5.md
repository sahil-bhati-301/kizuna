## Goal
Parse KRADFILE into a flat kanji → components list, ready to cross-check against KanjiVG in W02.

## Acceptance criteria (each must be testable)
1. The parser decodes KRADFILE's EUC-JP encoding and skips its comment lines.
2. Each line becomes a kanji with its component list, in file order.
3. The substitute characters KRADFILE's header documents for components with no good code point map to the intended component, through the W01-4 radical table where one applies.
4. A line that cannot be parsed is reported with its line number; parsing continues.
5. Output is deterministic (golden file) and carries `source`, `source_version` and `license`.
