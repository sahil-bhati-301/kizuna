# W02-3: JmdictFurigana alignment → `word_kanji` with phenomenon tags

## Goal
Link each kanji in each loaded word's headword to the reading it uses, tagged with the sound change, so context and reading analytics can attribute answers to readings.

## Acceptance criteria (each must be testable)
1. For each loaded word with kanji, one `word_kanji` row per kanji character of the headword: word, position (code-point index in the headword), kanji, reading ID, surface kana, phenomenon; kana-only words give no rows.
2. A segment whose kana equals a reading of that kanji (in hiragana; kun readings by stem, with the okurigana matching the text after the kanji) is `regular` and links that reading. Where several readings match, the rule in Q5 picks one; nothing picks by input order.
3. `rendaku` (first kana voiced, e.g. 人 ひと → びと), and `sokuon` (final つ/ち/く/き → っ, e.g. 学 がく → がっ) link the underlying reading; the cases in Q1 follow the owner's answer. Golden pairs: 人々, 学校, 出発, 一杯, 大人, 今日, 寿司.
4. A segment spanning several kanji is `jukujikun` (大人 おとな, 今日 きょう) with rows per Q2; an ateji-tagged form follows Q3; a word that JmdictFurigana lacks, or whose segment matches no reading even after the sound changes, is `irregular` with a reason in the report. 々 follows Q4.
5. The report lists counts per phenomenon, irregular words by reason, and kanji missing from the `kanji` rows; the same inputs give byte-identical output (golden file).
6. The `jmdict-furigana` source is pinned in the lock; its JMdict version and ours are both recorded in the report, and a word whose text and reading pair is absent is reported as version skew, not dropped.

## Test plan
- Unit: each phenomenon rule; okurigana matching; 々; multi-match tie-break.
- Property: positions are unique per word and point at a kanji character of the headword; every non-null reading ID exists and belongs to that row's kanji; concatenating surface kana of a word equals its reading wherever no jukujikun span is involved.
- Golden: fixture → sorted JSON rows plus report, byte-compared.

## OPEN-Q
- Q1 (Tier A): handakuten and double changes. 出発 しゅっぱつ has 発 はつ → ぱつ (h → p), and one phenomenon column per row. Options: (a) h → p counts as `rendaku`; a kanji with both a voicing change and sokuon gets `rendaku`; (b) add a value `handakuon` (outside the arch §3.1 list); (c) tag them `irregular`. Recommendation: a, because it stays inside the architecture's list and keeps the reading linked; record the rule in the module CLAUDE.md.
- Q2 (Tier A): jukujikun rows. Options: (a) every kanji in the span gets a row with `jukujikun`, `reading_id` null; the first row's `surface_kana` holds the whole span's kana, the others null; (b) as a, but every row repeats the span kana. Recommendation: a, so concatenating surface kana still gives the word's reading.
- Q3 (Tier A): ateji. JMdict tags whole forms (`ateji`), not kanji. Options: (a) in an ateji-tagged headword, kanji whose segment matches a reading stay `regular` (or rendaku/sokuon) and the rest are `ateji` with `reading_id` null; (b) every kanji in the form is `ateji`. Recommendation: a, because ateji often use real on readings (寿司 す・し), which should still count.
- Q4 (Tier A): the iteration mark 々 is not in KANJIDIC2. Options: (a) its row takes the preceding kanji as `kanji_literal` and is matched against that kanji's readings (人々 → 人 ひと, 人 びと rendaku); (b) skip 々 (no row). Recommendation: a, because the learner reads it as that kanji.
- Q5 (Tier A): several readings match one segment (生 う.まれる and うま.れる; on and kun with the same kana). Options: (a) prefer the reading whose okurigana matches the following text, then Jōyō over non-Jōyō, then on over kun, then the lowest reading ID; (b) link none and tag `irregular`. Recommendation: a, and count tie-breaks in the report.
