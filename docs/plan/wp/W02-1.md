## Goal
Turn the KanjiVG release file into typed `component` and `kanji_component` rows: a nested decomposition flattened with depth, order, position and role, plus a stroke count per kanji for the W02-5 cross-check.

## Acceptance criteria (each must be testable)
1. The parser streams the KanjiVG main XML file into one tree per kanji; `kanji_component` rows carry kanji, component slug, position, role, depth (1 = direct child of the kanji) and order (document order among siblings), with a stable sort and no duplicate primary keys.
2. Split elements (`kvg:part` 1, 2, …, e.g. 衣 around a middle part) become one component row, not one per part; positions map from KanjiVG names to the schema names by the table agreed in Q1.
3. Component glyphs pass through the W01-4 normaliser: NFC, radical variants linked to their Kangxi number (氵 → 85), and 月 used as 肉 (KanjiVG `kvg:original="肉"`) keyed ⺼ (W01-4 rule). A component with no Unicode code point gets the slug agreed in Q3 and its KanjiVG element ID in `kanjivg_id`.
4. Roles follow Q2: `kvg:phon` gives `phonetic`; the rest follow the agreed rule; nothing is guessed silently (unmapped cases are `unknown` and counted in the report).
5. Each kanji gets a stroke count (number of stroke paths) in the import result; golden: the fixture (持, 待, 特, 肝, 衣-split kanji, one kanji with a code-point-less element) gives byte-identical sorted JSON.
6. Every row carries `source`, `source_version`, `license` (CC BY-SA 3.0); the `kanjivg` entry is pinned in `content/sources.lock.yaml` and the file stored as the owner decides (week Q-S); a full-file smoke run reports kanji count, rows and `unknown` counts.

## Out of scope

## OPEN-Q
- Q1 (Tier A): position names. KanjiVG uses `left`, `right`, `top`, `bottom`, `nyo`, `nyoc`, `tare`, `tarec`, `kamae`, `kamae1`, `kamae2`, `kamaec` and sometimes none. Options: (a) map at every depth: left → `hen`, right → `tsukuri`, top → `kanmuri`, bottom → `ashi`, nyo/nyoc → `nyō`, tare/tarec → `tare`, kamae* → `kamae`, none → `none`; (b) the Japanese names only at depth 1, raw KanjiVG names below. Recommendation: a, because feature tags (`position:hen`) need one vocabulary, and depth already tells the two apart. Answered by the owner (session 12): recommendation taken.
- Q2 (Tier A): roles. KanjiVG marks phonetic elements (`kvg:phon`) and the classification radical (`kvg:radical`), not semantic roles. Options: (a) `phonetic` from `kvg:phon`; `semantic` for a `kvg:radical` element in a kanji that also has a `kvg:phon` element (phono-semantic compound); everything else `unknown`; `form` is left for curated overrides; (b) as a, but every `kvg:radical` element is `semantic`. Recommendation: a, because the radical is not always the meaning part, and `phonetic_series` (W03-1) needs `phonetic` to be precise. Answered by the owner (session 12): recommendation taken.
- Q3: slug for components with no code point. Options: (a) `kvg:` plus the element ID (per kanji instance, e.g. `kvg:05e73-g1`), so they never group across kanji; (b) a hand-made slug list now. Recommendation: a, and report the count; shared slugs can come from overrides in W03-3. Answered by the owner (session 12): recommendation taken.
- Q4 (Tier A, raised session 14 by spec-tester): primary-key collision. The PK is (kanji, component, depth, ord), and `ord` is order among siblings, so 競 gives (競, 立, 2, 1) twice (one 立 under each half). Options: (a) `ord` is the pre-order (document) index within the kanji, 1..n: unique, siblings still ascend, and the tree can be rebuilt from depth + ord, with no schema change; the property becomes "ord contiguous per kanji"; (b) add a parent column to `kanji_component` and the PK (schema and migration change in packages/content and packages/persistence, a deviation); (c) drop repeated identical rows (loses the second 立). Recommendation: a. Answered by the owner (session 14): recommendation taken.
- Q5 (Tier A): which `kvg:radical` values count for the Q2a semantic rule. Counts in the pinned file: general 10,562, tradit 1,356, nelson 1,176, jis 5. `general` means the traditional and Nelson radicals agree; `tradit` is the traditional (Kangxi) radical only. Options: (a) `general` and `tradit` only, matching the one Kangxi classification radical in the schema; nelson and jis stay `unknown`; (b) any value. Recommendation: a (哀: 口 `tradit` can be semantic, 亠 `nelson` cannot). Answered by the owner (session 14): recommendation taken.
- Q6 (Tier A): a split element whose parts sit at different depths or under different parents (哀: 衣 parts around 口). Options: (a) the merged row takes the depth, parent, position and place in order of `kvg:part="1"`; (b) the shallowest part. Recommendation: a (first in document order, deterministic). Answered by the owner (session 14): recommendation taken.
- Q7: two small defaults. `component.glyph` is NOT NULL, so a component with no code point needs one: use 〓 (U+3013 geta mark, the usual placeholder for a missing glyph), with the element in `kanjivg_id`. KanjiVG also uses `middle` (10 elements), which Q1 does not map: give it position `unknown` and count it in the report (AC4: nothing guessed). Recommendation: both. Answered by the owner (session 14): recommendation taken.
