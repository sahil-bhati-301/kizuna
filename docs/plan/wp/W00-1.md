## Goal
Set up the pnpm and Turborepo monorepo with strict TypeScript, linting, tests, boundary rules and terse verification scripts.

## Acceptance criteria (each must be testable)
1. `pnpm install` succeeds on a clean checkout and `pnpm -r build` runs through Turborepo.
2. TypeScript strict mode is on in the shared base tsconfig; a deliberate type error fails `pnpm verify`.
3. ESLint, Prettier and Vitest run through `pnpm verify:affected` (changed packages and dependents) and `pnpm verify` (all).
4. dependency-cruiser rules from arch §2.3 and §8.2 fail on a deliberate cross-module import that bypasses `src/index.ts`.
5. `scripts/verify-summary.mjs` prints `✅ all green (n tests)` on success, or per failure the test name, assertion and first five stack lines, capped at 60 lines.
6. Vitest uses the dot reporter, `--silent` and `--bail` locally.

## Out of scope
- CI workflow (W00-2). Database set-up (W00-6). Real module packages beyond an empty placeholder.

## Packages and files expected to change
- package.json, pnpm-workspace.yaml, turbo.json, tsconfig.base.json
- eslint and prettier config, vitest config
- .dependency-cruiser.cjs
- scripts/verify-summary.mjs (and tests in scripts/)

## Test plan
- Unit: verify-summary formatting for pass, fail and over-cap output (node --test).
- Golden: recorded vitest failure output → expected summary.
- Boundary: a fixture import that breaks the rules makes dependency-cruiser exit non-zero.
- Manual: run verify:affected after touching one package and confirm only it and its dependents run.
